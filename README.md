# 千年影戏 · 皮影数字馆

一个关于中国皮影戏的**沉浸式数字馆**。纵向九屏影像志 + 八个独立内容页 + 一条 AI 线索，
从「一盏灯、一张牛皮」讲到「两千年的影」，并把看展的人从旁观者变成动手的人：
可以让 AI 说戏人回答皮影的问题，也可以自己拟一句描述，让 AI 画一只影偶挂进自己的影箱。

- **在线演示**：<http://121.41.66.240>
- **代码仓库**：<https://github.com/Hzzzg02/qiannianyingxi>
- **参赛赛道**：2026 第九届「传智杯」全国大学生计算机大赛 · AI WEB 网页开发挑战赛
- **技术底色**：原生 HTML / CSS / JavaScript，前端零框架、零依赖、零构建

---

## 一、这是什么

传统非遗数字化的常见做法是「把展板搬到网页上」：一张大图、几段说明、翻不到头。
这个项目反过来做，先承认皮影的观看方式本来就是**暗场、灯亮、影动**，
于是把整站做成一条从暗到亮的纵向动线：首屏几乎全黑，只有一盏灯和一句话；
越往下走，纸色越暖，器物越具体，最后落到一张相片似的旧纸上收尾。

内容上不写空话。影史按文献与光源断代，流派按影系与唱腔分路，
工序按刀路和皮料分步，影箱按「头茬、鞦子、戳子、砌末、衬景、动物」六器分类，
出处尽量落到《汉书·外戚传》、联合国教科文组织名录、中国美术学院民艺博物馆藏品库这类可核对的来源上。

## 二、页面地图

### 首页：九屏纵向影像志

`index.html` 是一套自写的整屏翻页（非 fullPage.js），滚轮、键盘、触摸、右侧页码圆点、URL 锚点五种入口，
一次手势只翻一屏，动画没走完不接受新输入。

| 屏 | 锚点 | 内容 | 动效侧重 |
|---|---|---|---|
| 1 | `#page1` | 问一句，灯就亮（AI 入口） | 暗场 + 灯晕，输入框就地作答 |
| 2 | `#page2` | 流派地图：十四地、七大影系 | 彩色竖条墙 + 十张卡片上下交替飞入 |
| 3 | `#page3` | 台上四出（经典剧目） | 竖条内横向暗带随指针滑动 |
| 4 | `#page5` | 头条 · 速览 · 现场（影讯） | 三栏错落，矮屏自动压缩字号与行距 |
| 5 | `#page7` | 传灯有径（传承） | 竖标签指到才放大，其余四列一个像素不动 |
| 6 | `#page4` | 影箱六器 | 手风琴式列展开，指到的那列撑到三分之一宽 |
| 7 | `#page8` | 七道工序 | 图片带与工序名逐条点亮 |
| 8 | `#page6` | 传承与名册（分屏） | 左右分栏，满屏居中 |
| 9 | `#page9` | 关于本站 | 独立页脚屏，纸色收束 |

每一屏有各自的纸色与主色调，右侧页码圆点的提示条也跟着该屏换色（`--tip-*` 变量按 `body.is-viewing-N` 切换），
所以从暖纸走到冷灰再走回米纸，提示条不会突兀地跳成一种颜色。

## 三、AI 部分

站点里 AI 不是挂在页角的装饰按钮，而是三条真实通路，都走后端代理，Key 永不进前端。

### 1. 首屏就地问答（`assets/js/ask.js` → `POST /api/assistant`）

在首屏输入问题后**不跳页**，直接在原地展开一条答话：逐字打字机（16ms/帧）、
支持 `**加粗**` 与 `- 列表` 的轻量解析、`AbortController` 20 秒超时、
失败时降级成「说戏人没接上话」并给出对话页入口、`Esc` 收起、窄屏自动滚入视野。
想看完整上下文可以带着问题跳到 `chat.html?q=…`。

### 2. 影窗问答页（`chat.html`）

独立的对话页，多轮历史随请求带上。回答来源两级：先问 `/api/assistant`，
不通就落到内置的 16 条皮影知识库（按关键词命中打分），所以纯静态预览也能正常对话。

### 3. 影偶制作（`craft.html` → `/api/studio/cast` `/api/studio/catalog` `/api/studio/gen` `/api/studio/paint`）

三步把一个想法变成一只影偶：

1. **选角**：说清哪一路流派、哪一门行当、摆什么架子；
2. **检索**：拿这三样去皮影资料库里找同类形象，作为画稿参照；
3. **出图**：DeepSeek 把描述整理成结构化的绘制指令，智谱 CogView 按指令出图，
   单件、全身、白底；上色走 `/api/studio/paint`，五色（红、绿、黄、黑、白）分开控制。

出图落在 `uploads/ai/`，记录进 `server/data/db.json`，登录后挂进个人中心的影箱。

### Agent 工作流

本项目的开发过程本身也用了 Agent 协作：需求拆解、页面骨架生成、样式变量收敛、
跨屏几何冲突排查（矮屏溢出、末屏高度、绝对定位祖先）、部署与线上回归验收，
都由「读源码 → 起无头浏览器实测 → 按结果改 → 再实测」的闭环完成。
所有动效与布局结论以 1366×768、1440×900、1920×1080 三档实机量测为准，不靠目测。

## 四、技术实现

### 前端：零依赖

不用框架、不用打包器、不用 CDN 脚本，`file://` 双击也能跑（除需要后端的功能）。
13 个页面共用 17 个 CSS 与 31 个 JS，全部按模块拆开，靠 `?v=` 版本号破缓存。

几个值得一提的实现：

- **整屏翻页**：`translate3d` + 缓动，五种输入统一进一个 `go()`，动画未结束锁输入；
  指针位移超过 8px 才摘掉提示条的静默态（修掉「翻到新屏提示条还挂着」的悬停残留）。
- **进场动效**：CSS 变量驱动，`--rv-y` 控方向、`--rv-d` 控错位延迟，
  `cubic-bezier(.34,1.56,.64,1)` 复刻 Back 缓动；`prefers-reduced-motion` 全量降级。
- **提示条不裁字**：宽度 `auto` + `clip-path: inset(-10px 100% -10px 0)` 做擦除动画，
  不再按字数写死宽度，九个字以上的屏名也不会缺角。
- **降级路径**：900px 以下放弃劫持滚轮，改原生滚动 + `scroll-snap` 吸附整屏；
  窄屏另有 870px / 760px 两档矮屏断点，只压该屏内部间距，不动顶边锚点。
- **图片处理**：所有裁切、圆角、压缩都用无头 Chrome 的 canvas 完成，不引入图像库。
- **无障碍**：语义标签、`aria-label`、`role="menu"`、焦点可见、键盘可翻页。

### 后端：`server/server.js`（单文件 Node，无框架）

- 原生 `http.createServer`，18 个接口，JSON 文件库（`server/data/db.json`），无需数据库服务。
- 邮件验证码、图形验证码、登录态、改密、找回、帖子与回帖、影偶记录与出图。
- 配置优先取环境变量，其次 `server/config/*.json`，最后 `/etc/qnyx/*.json`；
  Key 只在服务端，前端拿不到。
- 无 Key 时可开 `QN_DEEPSEEK_MODE=mock` / `QN_ZHIPU_MODE=mock` 跑通全流程。

### 部署

阿里云 Ubuntu 22.04 + nginx 直出静态文件，`/api/` 反代到 `127.0.0.1:3100`，
后端由 systemd 单元 `qnyx.service` 托管，Key 放 `/etc/qnyx/`。

## 五、本地运行

```
# 1. 起后端（3100）
node server/server.js

# 2. 另开一个终端，起静态站 + 反代（8092）
node server/dev.js

# 3. 打开
http://127.0.0.1:8092
```

不需要 `npm install`，没有第三方依赖。

只想看页面、不接 AI：直接双击 `index.html` 即可，
问答会自动降级到内置知识库，影偶出图会提示未接入。

配置见 `.env.example`，复制一份填上自己的 Key：

```
cp .env.example .env
cp server/config/deepseek.example.json server/config/deepseek.json
cp server/config/zhipu.example.json   server/config/zhipu.json
```

> `server/config/*.json`、`server/data/db.json`、`uploads/ai/` 已在 `.gitignore` 中，真实 Key 不进仓库。

## 十、已知限制

- 数据层是 JSON 文件，适合演示与小规模使用，并发写入需换数据库。
- AI 出图依赖第三方接口，高峰期可能排队；失败会明确提示，不会静默卡住。
- 邮件验证码需要 SMTP 配置，未配置时改为写入 `server/data/mail.log`（开发模式）。
